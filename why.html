What it is

A data centre from the machines you own.

01 · Install

One package per Linux machine

Install the coordinator on one machine and the agent on the others. Each machine joins in one command, with its own certificate.

02 · Pool

Your machines become one cluster

Diffuse measures every machine and places each model where it runs best: on a workstation, on a GPU server, or across several machines at once.

03 · Use

Your teams use it like OpenAI

Applications, coding assistants and a chat interface call an OpenAI-compatible API on your network. Fine-tune and distil on the same machines.

How it works

Your machines, one private AI platform.

A coordinator

One machine runs the control plane.

It holds your models, your accounts and your keys, issues every machine its certificate, and keeps the audit trail.

Nodes

Every other machine computes.

Workstations, servers and GPU machines join with one command. Diffuse measures each one and places every model where it runs best, on one machine or across several.

Continuous batching

Many people, one model, no queue.

Each machine serves many conversations at once and remembers each person’s context, so the next answer starts in milliseconds.

One endpoint

Your teams see one API.

Add machines, add replicas, move models: applications keep calling the same address on your network.

Technical review

Four questions before rollout.

Machine identity

A network address can change.

Machines authenticate each other with certificates. The operator can revoke an identity.

Application access

An application only needs access to its own model.

Set the scope and expiry of an API key. A reporting service can lose access on the agreed date.

Administrative trail

A review asks you to reconstruct a change.

The audit trail records the actor, administrative actions and refusals. Prompt and response content stays out of the audit log.

Isolated network

The deployment site operates offline.

Import models locally and install the signed licence file. The product checks the licence on site.

What goes wrong

The dev-tool deployment, examined.

Access

An open port is an open door.

The usual inference server answers whoever reaches its port: no token, no account, no limit. Diffuse gives each application a scoped key and each machine a certificate.

Transport

Plaintext across the network.

Prompts and documents cross the network unencrypted because the default was http. Between Diffuse machines every connection is mutual TLS, and no mode turns it off.

Identity

Nobody is anybody.

Without an account or a key, no request can be attributed after the fact. Diffuse records the key, and the person behind a gateway, on every request.

Audit

Nothing is written down.

A log of crashes is not an audit trail. Diffuse records who deployed which weights, who revoked what and who was refused, and exports it for an auditor.

Governance

No centre, so no control.

Each team runs its own server. Diffuse puts every team’s machines under one coordinator, with roles and one place to revoke access.
