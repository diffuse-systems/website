Pourquoi Diffuse

Votre IA, sous contrôle.

Un modèle qui répond sur un poste est un bon début. Pour le partager entre équipes, il faut aussi savoir qui peut l’appeler, où il tourne et comment retirer un accès.

✓Qui peut appeler cette API ?

Ce que c’est

Un datacenter avec vos propres machines.

01 · Installer

Un paquet par machine Linux

Installez le coordinateur sur une machine et l’agent sur les autres. Chaque machine rejoint le parc en une commande, avec son propre certificat.

02 · Mutualiser

Vos machines deviennent un cluster

Diffuse mesure chaque machine et place chaque modèle là où il tourne le mieux : sur un poste, sur un serveur GPU, ou sur plusieurs machines à la fois.

03 · Utiliser

Vos équipes l’utilisent comme OpenAI

Applications, assistants de code et interface de chat appellent une API compatible OpenAI sur votre réseau. Adaptez et distillez sur les mêmes machines.

Comment ça marche

Vos machines, une plateforme d’IA privée.

Un coordinateur

Une machine porte le plan de contrôle.

Elle conserve vos modèles, vos comptes et vos clés, délivre son certificat à chaque machine et tient la piste d’audit.

Des nœuds

Toutes les autres machines calculent.

Postes, serveurs et machines GPU rejoignent le parc en une commande. Diffuse mesure chacune et place chaque modèle là où il tourne le mieux, sur une machine ou sur plusieurs.

Continuous batching

Beaucoup de personnes, un modèle, pas de file.

Chaque machine sert de nombreuses conversations à la fois et garde le contexte de chacun, pour que la réponse suivante démarre en quelques millisecondes.

Un seul point d’accès

Vos équipes voient une seule API.

Ajoutez des machines, des répliques, déplacez des modèles : les applications appellent toujours la même adresse sur votre réseau.

Ce qu’il expose

L’API OpenAI, sur votre réseau.

/v1/chat/completions

Chat et outils

Réponses en streaming, appels de fonctions, sorties JSON structurées et raisonnement séparé, avec les bibliothèques que vos développeurs utilisent déjà.

/v1/responses · /v1/embeddings

Agents et recherche

L’API Responses pour les outils agentiques, et les embeddings pour votre propre recherche sémantique, depuis le même point d’accès.

Console · CLI · /metrics

Exploitation

Une console web pour les personnes et les rôles, une ligne de commande pour chaque action, des métriques Prometheus et une piste d’audit exportable.

Conçu pour

RAG, chat, chatbots et code.

RAG

Vos documents ne sortent jamais.

Embeddings, extraction de PDF et génération tournent sur vos machines : le corpus le plus confidentiel peut être interrogé et résumé avec l’IA.

Chat

Un ChatGPT pour votre organisation.

Une interface de chat avec comptes et authentification unique, où les conversations de chacun restent privées et chaque requête est attribuée.

Chatbots

Des API de production pour vos produits.

Clés limitées, quotas par personne et réponses en streaming : placez un assistant devant vos clients ou vos équipes, sur un matériel que vous maîtrisez.

Code

Des agents de code sur votre propre code.

OpenCode, Continue et d’autres assistants appellent le même point d’accès, avec appels d’outils et un cache qui garde les longues sessions rapides. Votre code reste chez vous.

Sécurisé de bout en bout

Des données sensibles, en toute sérénité.

Chiffré entre chaque machine

TLS mutuel sur chaque connexion.

Chaque machine prouve son identité avec un certificat de votre propre autorité, et tout ce qui circule entre elles est chiffré.

Des accès que vous décidez

Comptes, rôles et clés d’API limitées.

Donnez à chaque application exactement les modèles dont elle a besoin, pour la durée voulue, et retirez un accès en une commande.

Une trace pour chaque action

Qui a déployé, qui a appelé, qui a changé quoi.

La piste d’audit consigne chaque action d’administration et chaque requête, et s’exporte proprement pour vos auditeurs. Les prompts et les réponses n’y figurent pas.

Rien ne quitte votre réseau

Ni télémétrie, ni cloud, ni appel à l’éditeur.

Les modèles sont importés localement et la licence est vérifiée sur place : toute la plateforme fonctionne même sur un réseau isolé.

Revue technique

Quatre questions avant le déploiement.

Identité des machines

Une adresse réseau peut changer.

Les machines s’authentifient mutuellement par certificat. L’opérateur peut révoquer une identité.

Accès des applications

Une application n’a besoin que de son modèle.

Une clé d’API peut être limitée dans sa portée et sa durée. Le service de reporting peut ainsi perdre son accès à la date convenue.

Trace administrative

Une revue demande de reconstituer un changement.

Le journal consigne l’acteur, les actions administratives et les refus. Les prompts et les réponses restent hors du journal.

Réseau isolé

Le site fonctionne sans accès Internet.

Importez les modèles localement et installez le fichier de licence signé. Le produit vérifie la licence sur place.

Ce qui coince

Le déploiement d’outil de dev, examiné.

Accès

Un port ouvert est une porte ouverte.

Le serveur d’inférence habituel répond à quiconque atteint son port : ni jeton, ni compte, ni limite. Diffuse donne à chaque application une clé limitée et à chaque machine un certificat.

Transport

Du texte en clair sur le réseau.

Les prompts et les documents traversent le réseau sans chiffrement parce que le défaut était http. Entre les machines Diffuse, chaque connexion est en TLS mutuel, sans mode qui le désactive.

Identité

Personne n’est personne.

Sans compte ni clé, aucune requête ne peut être attribuée après coup. Diffuse consigne la clé, et la personne derrière une passerelle, pour chaque requête.

Audit

Rien n’est écrit.

Un journal de pannes n’est pas une piste d’audit. Diffuse consigne qui a déployé quels poids, qui a révoqué quoi et qui a été refusé, et l’exporte pour un auditeur.

Gouvernance

Pas de centre, donc pas de contrôle.

Chaque équipe fait tourner son propre serveur. Diffuse place les machines de toutes les équipes sous un coordinateur, avec des rôles et un seul endroit pour révoquer un accès.
